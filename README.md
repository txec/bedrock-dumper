# bedrock-dumper

Dynamic memory and function offset dumper for Minecraft: Bedrock Edition (`Minecraft.Windows.exe`).

## Overview

Unlike conventional pattern dumpers that rely on fragile function prologue bytes (which frequently break between compiler optimizations or minor game updates), `bedrock-dumper` uses a dynamic resolution technique:

1. **Anchor String Scanning**: Scans `.rdata` for immutable asset identifiers (e.g., `"textures/ui/pointer"`).
2. **Instruction Disassembly (Zydis)**: Disassembles `.text` instructions in real time to locate RIP-relative references (`[rip + disp]`) pointing to the string.
3. **PE Exception Table Resolution (.pdata)**: Performs an `O(log N)` binary search on the x64 PE exception directory (`RUNTIME_FUNCTION` entries) to determine the exact function boundary and entry point.
4. **Resilient Fallback**: Includes a backwards INT3 padding scan and pattern scanner fallback if required.

## Dumped Offsets

Currently supported offsets:

- `ClientInstance::Update`:
  - Resolved via dynamic xref to the `"textures/ui/pointer"` string.
  - Automatically handles ASLR and computes Relative Virtual Address (RVA).

## Prerequisites

- Windows 10/11 (64-bit)
- Visual Studio 2022 (with "Desktop development with C++" workload)
- CMake 3.20 or newer
- Git (for CMake FetchContent to pull dependencies)

Dependencies (`spdlog`, `zydis`, `nlohmann_json`) are fetched and compiled automatically via CMake FetchContent.

## Building

Clone the repository and build using CMake:

```powershell
# Configure the build directory
cmake -B build -G "Visual Studio 17 2022" -A x64

# Compile Release binary
cmake --build build --config Release
```

The compiled binary will be placed at `build/Release/bedrock-dumper.exe`.

## Usage

1. Launch Minecraft: Bedrock Edition (`Minecraft.Windows.exe`) and wait until it loads into the main menu.
2. Run the dumper executable:
   - Double-click `run.bat`, or
   - Execute from terminal:
     ```powershell
     .\build\Release\bedrock-dumper.exe
     ```
3. The dumper will attach, analyze memory, and output the resolved offsets.

## Output Formats

The dumper generates two output files in the current working directory:

### C++ Header (`offsets.hpp`)

```cpp
/*
 * Generated by bedrock-dumper v1.0
 * Target: Minecraft.Windows.exe
 * Elapsed: 8236 ms
 * Total Offsets: 1
 */

#pragma once
#include <cstdint>

namespace Offsets {
    namespace ClientInstance {
        constexpr uintptr_t Update = 0xD44840; // xref to textures/ui/pointer
    }
} // namespace Offsets
```

### JSON (`offsets.json`)

```json
{
    "_metadata": {
        "project": "bedrock-dumper",
        "version": "1.0",
        "timestamp": "2026-09-26 17:51:15 UTC",
        "total_offsets": 1
    },
    "offsets": {
        "ClientInstance": {
            "Update": {
                "rva": "0xD44840",
                "decimal": 13912128,
                "comment": "xref to textures/ui/pointer"
            }
        }
    }
}
```

## Adding New Stages

The project uses a modular stage system inspired by modern PE memory dumpers:

1. Create a new `.cpp` file in `src/dumper/stages/` (e.g. `src/dumper/stages/my_stage.cpp`).
2. Implement your resolution logic inside a `dump()` function.
3. Register the stage with `REGISTER_STAGE(my_stage)`.

The engine automatically invokes registered stages without requiring modifications to `main.cpp`.
